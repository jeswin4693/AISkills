# AI Engine Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** One provider-independent model service (task tiers, one retry policy, usage, redaction, Anthropic adapter) that every builder shares, with no behaviour change until a new setting is used.

**Architecture:** A thin `skillforge/ai/` layer sits in front of the existing `LLMProvider` adapters. `AIService` is itself an `LLMProvider`, so builders and tests keep their `provider` parameter. Adapters make one HTTP attempt and classify errors; the service owns routing, retries, budgets, usage and redaction.

**Tech Stack:** Python 3.13, pydantic 2, openai 3.52 and anthropic 2.9 SDKs (both already pinned), SQLAlchemy + Alembic, pytest. Frontend: Next.js, vitest.

**Spec:** [docs/ai-engine.md](../../ai-engine.md)

## Global Constraints

- Run Python from `backend/` with `C:\dev\venvs\aiskills\Scripts\python.exe` (Git Bash: `/c/dev/venvs/aiskills/Scripts/python.exe`); tests: `python -m pytest -q`.
- Tests are offline: `MockProvider` or `httpx2.MockTransport`; no test reads the real `.env` or calls a hosted model.
- No new library. Never hardcode a model name. Keys come only from the environment or `.env`; never print, log, store or document one.
- Every existing test keeps passing; a test may change only where this plan says so.
- New code in `ai/` never calls `load_dotenv`; it receives an environment mapping.
- Gemini remains the default; with no new `LLM_*` setting the same prompts go to the same model.
- After the slice: README, `docs/roadmap.md`, `docs/ai-engine.md` updated; commit; push (`timeout 75 git push origin main`). Commit messages end with `Co-Authored-By: Claude Sonnet 5.5 <noreply@anthropic.com>`; check `git diff --cached` for `.env` or key fragments first.

## Review Focus

- A bare `MockProvider` must behave exactly as before: same retry counts, same errors (task 6 re-runs every old test).
- A key must never appear in an error message, a usage row or the status payload, even when the provider echoes it (task 6, task 8).
- A broken tier override (missing key, bad number, other provider without a model) must fail at start-up naming the variable, never fall back silently (task 5).
- A 429 with a huge `Retry-After` must stop with a message, not sleep for minutes (task 4).
- Escalation and the cache must add no calls and no behaviour when not configured (tasks 9, 10).
